# Изменения

## 3.0.0

**Разделение на два сервера: панель и edge.**

- Новые роли: сервер панели (бот, панель, Remnawave, база) и edge (мини-приложение, страница подписки, XBM, вебхуки).
  Панель сама подключается к edge по WireGuard; на edge нет адреса, домена и секретов панели.
- `edge-ingress` — единственная дверь из туннеля: белый список путей, чистка заголовков, лимиты, подстановка токена
  Remnawave для страницы подписки, сканер утечек адреса панели в каждом ответе.
- `edge-agent` — команды панели на edge (HMAC-подпись, только из туннеля): настройки XBM, отправка почты, смена доменов
  с выпуском сертификатов, обновление.
- API разделён на два процесса: `api` (панель и все фоновые задачи) и `api-public` (только мини-апп, без фоновых задач).
- Установщик: роли panel/edge, коды сопряжения, перенос данных со старого сервера, файрвол, команды `blinvpn` и
  `blinvpn-edge`: смена доменов, IP edge, переезд edge, обновление обоих серверов одной командой.
- Панель: «Настройки → Серверы» (состояние edge, домены, адреса вебхуков), XBM-вкладка под edge.

**Мини-приложение:**

- «Подписка → Дополнительно → Сброс ключа»: перевыпуск ссылки подписки через официальный API Remnawave
  (`POST /api/users/{uuid}/actions/revoke`), новая ссылка сразу показывается пользователю. Не чаще раза в 24 часа:
  кнопка неактивна и показывает таймер; ограничение атомарное на сервере, неудачный сброс попытку не тратит.

**Чёрный список Telegram ID** (`ban-vpn/blacklist.txt`, обновление раз в час):

- Проверка при каждом входе, а не только через Telegram: вход по почте, по сохранённой сессии и с протухшим initData.
- Если Remnawave была недоступна в момент бана, ключ отключается повторно, пока не получится (раньше ключ оставался рабочим).
- Не удалось скачать список — повтор через 5 минут, а не через час.

**Поддержка:**

- История переписки хранится бессрочно (раньше закрытые обращения исчезали через сутки).
- Когда S3 заполнено на 98% (свободно меньше 2%), удаляются самые старые вложения — файлы, фото, видео —
  пока занятость не опустится до 95%. Сначала из закрытых обращений, из открытых — в последнюю очередь.
  В чате на месте файла остаётся пометка «файл удалён», текст сообщения сохраняется.
- Текст переписки удаляется только в крайнем случае: вложений не осталось, а S3 всё ещё заполнено (место занимают
  резервные копии базы). Удаляются самые старые закрытые обращения целиком, не чаще раза в сутки и не раньше,
  чем обновятся бэкапы. Открытые обращения не удаляются никогда.
- Резервные копии базы в том же бакете учитываются в занятом месте; в «Настройки → Хранилище S3» видно, сколько
  занимают вложения и сколько — бэкапы.

**Безопасность и исправления (полезны и сами по себе):**

- Реальный IP клиента — только от своего прокси (раньше `CF-Connecting-IP` подделывался → обход лимита входа в панель).
- Ссылка подписки больше никогда не строится из адреса Remnawave.
- Письма уходят с edge; EHLO и Message-ID без имени сервера.
- Двойные чеки «Мой налог» при обработке очереди несколькими процессами — захват строки в БД; прерванная отправка
  уходит на ручную проверку, а не переотправляется вслепую.
- Вебхуки: IP отправителя (ЮKassa, Platega) только из доверенного заголовка; адрес вебхуков без запасного домена мини-аппа.
- WATA: принудительное обновление публичного ключа — не чаще раза в минуту.
- Капча: тревога в форум, если сервис проверки недоступен (вход пропускается без капчи).
- Страна для капчи — по HTTPS (`api.country.is`), запасной ip-api.com.
- Тексты для пользователей (рассылки, ответы поддержки, оферта, политика) с адресом панели не сохраняются.
- nginx панели: `Referrer-Policy: no-referrer`, CSP, `X-Robots-Tag`, `ssl_reject_handshake` для запросов по IP.
- XBM: токен edge к апстриму, IP клиента из `X-Real-IP`, служебные заголовки апстрима не уходят клиенту.
