# XBM в BlinVPN: балансировщик подписки

XBM (Xray Balancer Middleware, автор — Haxonate, см. [NOTICE.md](NOTICE.md)) стоит между
клиентами и Remnawave. Он отдаёт **только подписку**: трафик идёт к нодам напрямую.

```
Happ / Clash / Sing-box ──► nginx подписки ──► XBM ──► Remnawave
Браузер                 ──► nginx подписки ──► страница подписки (как раньше)
```

**Хосты в Remnawave — для XBM, хосты в панели — для пользователей.**

По умолчанию у пользователя в Happ, Incy, Clash и т. д. **одна строка — «Авто-выбор»**,
даже если в Remnawave 50 хостов: клиент сам пингует их все и держит самый быстрый.

## Панель → «Балансировщик»

Если XBM ещё не подключён, здесь открывается мастер установки. После подключения —
настройка строк подписки. Вернуться к установке можно кнопкой с шестерёнкой.

1. **Авто-выбор** — название строки и (по желанию) шаблон Xray JSON из Remnawave.
2. **Хосты для пользователей** — строки подписки под авто-выбором, в заданном порядке.
   Кнопка «Добавить хост»:
   | Поле | Что делает |
   |---|---|
   | **Название** | Его видят пользователи, например «🇩🇪 Германия». |
   | **Хосты Remnawave** | От одного до любого числа (de1, de2, de3…), названия любые. Клиент держит тот, где меньше пинг. Хост Remnawave может входить только в один хост панели. |
   | **Белые списки** | В авто-выборе эти хосты — резерв: подключаются, только если ни один обычный сервер не отвечает, даже если пинг у них меньше. |
   | **Описание** | `meta.serverDescription`, до 30 символов. |
   | **Шаблон Xray JSON** | Шаблон из Remnawave → Subscription → Templates (DNS, маршрутизация). Подключение к серверам всё равно берётся из хостов. |
3. **Хосты Remnawave** — справочно: где используется каждый хост. Хост, не входящий ни в один
   хост панели, работает только внутри авто-выбора.

Справа — «Так увидит пользователь» (схема по несохранённым настройкам) и «Проверить на
пользователе» (настоящая подписка через XBM). Все настройки каждого хоста Remnawave
(протокол, SNI, порт…) сохраняются. Хосты выбираются по списку, переименование в
Remnawave подхватывается само (сверка раз в минуту). После «Сохранить» XBM подхватывает
изменения за пару секунд, без перезапуска.

Как работает резерв: в авто-выборе обычные сервера сравниваются по пингу, а белым спискам
XBM даёт «штраф» 10 секунд при таймауте проверки 1 секунда. Поэтому белые списки
выбираются, только когда ни один обычный сервер не отвечает, и клиент вернётся на обычные,
когда они оживут. В Clash — группа fallback «обычные → резерв»; в Sing-box резерв в
авто-выбор не входит (там нет fallback) и доступен отдельной строкой.

## Установка: панель → «Балансировщик» (мастер, если ещё не подключено)

Нужен сервер, где стоят Remnawave и страница подписки по docs.rw (контейнер
nginx подписки, сеть Remnawave). Контейнер nginx выбирается из списка Docker,
а не зашит как `remnawave-nginx`.
Команды на сервере выполняет помощник `blinvpn-host` (ставится при установке или
обновлении через `install.sh`): панель только ставит ему задания из белого списка.

Мастер ведёт по шагам и проверяет каждый:

1. **Установить XBM.** Адрес панели (обычно `http://remnawave:3000`) и домен подписки;
   запускается контейнер `blinvpn-xbm`. Если XBM уже стоял отдельно
   (`/opt/xray-balancer-mw` или старое имя `xray-balancer-mw`), он заменится.
2. **Remnawave → Response Rules.** VPN-клиентам должен отдаваться `XRAY_JSON`: правила
   копируются кнопкой (они же — в [response-rules.json](response-rules.json)). Кнопка
   «Проверить» убеждается, что Remnawave отдаёт Xray JSON.
3. **Подключить XBM к подписке.** Правится только блок домена подписки в
   `/opt/remnawave/nginx/nginx.conf` (панель в том же файле не трогается):
   - перед правкой делается резервная копия, затем `nginx -t`; при ошибке всё возвращается само;
   - после перезагрузки nginx подписка проверяется (заголовок `X-XBM`), и если она не
     отвечает, правка откатывается.
4. **Настройка строк**: после подключения мастер предложит перейти к хостам для пользователей.

**Если XBM упадёт или будет остановлен**, nginx сам отдаст обычную подписку без
авто-выбора. Люди не останутся без подписки.

**Отключить:** тот же раздел → «Отключить от подписки». Конфиг nginx возвращается
к исходному, байт в байт.

## Clash / Koala: у Reality-серверов нет пинга

Это не XBM. Начиная с Xray 26.7.11 нода не пускает по Reality старые клиенты, а Clash
(Mihomo) представляется версией 1.8.2. В Remnawave → Config Profiles в каждом
Reality-инбаунде добавьте в `realitySettings`: `"minClientVer": "1.8.2"`.
